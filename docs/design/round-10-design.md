## A. 閃退

### 手段先於結論

GDScript 冇任何「捉得住 crash」嘅 API。一個真 process 死亡(SIGSEGV / abort /
OOM / 引擎 CRASH_COND)唔會俾腳本機會執手尾,所以「等下次閃退嗰陣開 debugger」
喺一部電話上面永遠做唔到。唯一行得通嘅係:**閃退之前就已經寫低咗**。

兩層,兩層都係常設功能唔係臨時工具:

1. **引擎 file logging**(`project.godot` 嘅 `debug/file_logging/*`)→
   `user://logs/godot.log`。入面有 `push_error` / 腳本錯誤嘅完整 stack trace,
   而且係引擎層 flush,所以 crash 前嗰幾行留得低。
   PC 上面呢個設定本身就已經預設開,但 **Android / Web 唔係** —— 而閃退報告
   正正就係嚟自嗰兩邊。所以要明寫。
2. **`Crash.gd` 未關門標記 + 麵包屑**。開場即刻寫一個 session marker,
   正常退出先刪。下次開場見到舊 marker 仲喺度 = 上次非正常結束 →
   將嗰次嘅麵包屑抄入 `user://logs/crash.log`。

麵包屑係**事件**唔係逐幀:場景切換、開場收場、放塔、轉速、語言切換。
一單閃退報告冇呢啲就淨係得一句「佢閃退咗」,而嗰句係冇用嘅。

Marker 入面記 pid:同一部機開兩個 instance 嘅時候,第二個唔會將第一個嘅活
marker 當成一單根本冇發生過嘅閃退。

### Soak test

`test/SoakTest.gd`。同其餘測試相反 —— 佢**唔**手動餵 delta,而係行真幀、真
`_process`、真 `Engine.time_scale`、真 `change_scene_to_file`,因為閃退嘅成因
通常就正正喺嗰啲被手動步進繞開咗嘅位。

兩個階段缺一不可:

* **A 孤立戰鬥**:一場 40 座塔、5x、魔法連放、中途賣塔轉速加塔、開關抽屜、
  暫停、圖鑑 overlay,打到 boss 死或者 110 秒遊戲時間。快,所以做得多。
* **B 真流程**:主選單 → 選關 → 戰鬥 → 結算 → 主選單 → 選單畫面。
  `change_scene_to_file` 係**延遲**釋放成個現行場景,而戰鬥收場嗰陣仲有計時器、
  tween、pool 節點喺度 —— A 嗰種 `queue_free` 唔行同一條路。

判斷標準係 **exit code**,唔係腳本自己講嘅一句 PASS。

## B. 巫教族反制

規則:掛落**現有**塔/魔法,唔加新塔。

問題係「治療 / 加速光環冇針對性解法」,所以答案要分兩種:
**削治療**同**熄光環**。兩樣都要有塔方案同魔法方案,先至唔會變成
「一個魔法解決一切」。

| 方向 | 載體 | 效果 |
|---|---|---|
| 削治療 | 毒液塔「重傷」 | 中毒目標所受治療 −50%(隨每層毒傷軸加深) |
| 削治療 | 劇毒瘴氣 | 範圍內敵人治療效果 −70% |
| 熄光環 | 磁暴脈衝 | 暈眩期間光環類技能(治療/加速)完全失效 |
| 破魔抗 | 光束塔「融甲」 | 由淨削護甲擴展為護甲同魔抗一齊削 |
| 點名 | 天雷誅殺 | 對支援型單位(巫師 / 大祭司)增傷 |
| 點名 | 狙擊塔 / 導彈塔 | 目標優先選項加「優先巫師」 |

「治療減免」做成一個**通用狀態**(`Monster.heal_cut`)而唔係逐個機制各寫一套:
新增嘅治療來源自動受制,而唔係要人記得去補。同 boss 回復上限一樣,一個
enforcement point。

## C. 聖光塔 —— 全圖光環

`aurarange` 呢條軸唔要,因為佢係「買半徑」—— 一條純粹買覆蓋率嘅軸,冇任何
決策喺入面。改成全圖之後個決策變成「擺唔擺第二座」,而嗰個先係一個真選擇。

* 攻速加成:全圖,冇範圍限制。
* 疊加遞減:第一座 100%、第二座 60%、第三座 30%、之後 15%。防聖光海。
* 舊「光環範圍」軸嘅魔晶**全退**,新軸「聖光強度」由 0 起 —— 照詛咒塔嗰套
  遷移(`Meta.SAVE_VERSION` 2),連提示連 test。
* 新軸「聖光強度」:光環同時提供小量**攻擊力**加成,所以聖光塔由「攻速機」
  變成「全隊放大器」,而佢自己輸出唔強 —— 一個塔位換全場,係一個
  真取捨,同詛咒塔(局部放大 + 經濟)分得開。
* 視覺:受惠塔身上微金光粒子 + 聖光塔本體光柱。冇表現嘅光環等於冇光環。

## D. 進化系統

### 規則

* 每種塔 / 魔法 3 級 tier。現有 = tier 1。
* 進化條件:**該項全部升級軸課滿 15 級** + 進化魔晶費(隨 tier 遞增)。
* 進化後:基礎能力大幅躍升、保留原特性、**加一個新機制**、外觀進化,
  全部升級軸重開 15 級,費用曲線接續(貴過 tier 1 段)。

### 三個唔顯然嘅決定

1. **升級步長跟住 tier 一齊放大。** 唔係嘅話 tier 3 一座塔嘅
   「+3 攻擊 / 級」相對佢自己嘅基礎值細到冇意義,六條軸就變成裝飾。
   所以 `add` 類步長乘同一個 tier 倍率;`prob` 類唔乘(機率封頂 1.0)。
2. **費用曲線接續,唔係重頭計。** `upgrade_cost(base, lv)` 收一個
   **全域級數** `lv + 15*(tier-1)`,所以 tier 2 嘅第一級已經貴過 tier 1 嘅
   第十五級。呢個係「進化唔係重來,係繼續」呢句嘢喺數字上面嘅講法。
3. **升級軸嘅等級喺進化嗰刻歸零,但唔退錢。** 已經課落去嘅嘢化成
   tier 躍升本身。退錢會令進化變成一個免費嘅 respec。
