## Part A — 風險合約關

### 概念

逢 7 嘅倍數關(7、14、21…98)係合約關。整場關卡切成五段,每段開波前攤三張
「合約」俾玩家揀一張,每張卡係一個**怪物增益 ↔ 獎勵倍率**嘅交易。揀咗嘅
增益疊落之後每一段,貪心落去雪球越滾越大。

第 100 關**唔係**合約關:佢係終極戰,唔應該有第二套規則疊落去。

### 三個結構性決定

**1. 增益加法疊,倍率乘法疊(有封頂 ×3.0)。**
加法嘅增益永遠算得出(生命 +10% 揀五次就係 +50%),乘法嘅倍率先會令連續貪心
有雪球感 —— 而雪球一定要有牆。`CONTRACT_MULT_CAP = 3.0` 真係會咬:全程揀最高
倍率係 1.45^5 = 6.4,封到 3.0。

**2. 最低風險嗰檔唔係「無增益 ×1」。**
一張 ×1 嘅卡會令穩陣玩家喺合約關嘅收入同普通關一模一樣,而 Gate 8 要求佢係
1.1–1.3 倍 —— 即係話「唔賭」都應該賺少少,「賭」先係賺多。所以最安全嗰檔係
「細增益 ×1.05」。五張 risk-0 卡連揀五次 = 1.05^5 ≈ 1.28,啱啱好落喺目標帶。

**3. 抽過嘅卡唔會再抽到。**
同一張卡揀五次係一條冇決策嘅路。唔重複逼玩家喺唔同軸之間揀,而每一軸都有
唔同嘅反制(硬 → 破甲;快 → 控場;護 → 削甲/真傷;回復 → 減療;免疫減速 →
凍結/暈眩;精英 → 見下)。

### 倍率對敗仗一樣適用

條 brief 話「倍率適用與否你定,寫明」。**適用。** 合約押嘅係「呢一場」,唔係
「呢一場嘅勝利」—— 一個只喺贏嘅時候兌現嘅倍率會令高風險合約變成純粹嘅自殺,
而 brief 亦都講明「揀咗高風險合約打輸,都照 Gate 1 規則有輸場晶石」。

反 farm 嘅兩道閘照行:`LOSE_MIN_TIME`(開場十秒內結束唔派)同
`LOSE_REPLAY_FRAC`(打過嘅關卡輸咗只派三成),所以「入去合約關即刻投降刷倍率」
呢條路仍然封住。

### UI

* 開波前彈三選一卡片,**真 `get_tree().paused`**,唔係一個自訂 flag ——
  場上有怪、有子彈、有地面效果、有塔喺度數冷卻,而佢哋全部係獨立節點。
  一個只擋 `Battle._process` 嘅 flag 會令怪物繼續行。
* 卡面顯示:名 / 風險色帶(綠琥珀紅)/ 增益 / 倍率 / **簽下後嘅總倍率**。
  最後嗰行先係玩家真正要比較嘅嘢。
* 卡面文字全部由 `GameData.contract_buff_text()` / `contract_mult_text()` 出,
  唔喺 UI 度另寫一次 —— 一份手寫嘅卡面遲早會同數據講唔埋。
* 戰鬥 HUD 常駐一個細 badge:`合約 n/5  ×倍率`,撳一撳攤開當前總狀態。
* 選關介面:合約關紫底 + 「◆ 風險合約」,第 100 關赤紅底 + 「★ 最終決戰」。

## Part B — 100 關 + 經濟/難度總 rework

### 第 0 步:關卡總數

原本嘅關卡生成係**無限**嘅(`level_config(n)` 對任何 n 都出到嘢),而選關介面
顯示到「已通關 + 1」。即係話「而家有幾多關」冇一個數 —— 有數嘅係「量度同設計
覆蓋到邊」,而嗰個係第 40 關(`BalanceSim --evolve` 嘅 `EVOLVE_LEVELS`)。

而家釘死:`GameData.FINAL_LEVEL = 100`,選關介面封頂喺 100,第 100 關特製。

**進化解鎖節點唔使改。** tier 2 @ 24、tier 3 @ 38 呢兩個數係**商店解鎖**嘅
節奏,而必需點係 41 / 71 —— 中間分別有 17 關同 33 關嘅儲資源期,遠多過
「畀玩家有段時間儲資源進化」所需。實測 A2 大約喺第 33-38 關真係買得起
tier 2,A3 大約喺第 62-68 關買得起 tier 3,兩個都喺必需點之前。

### 難度指數:一個新概念

**舊版:** `wave_scale` 就係難度。但一關嘅實際壓力唔淨止係「一隻怪幾多血」,
仲有「一隻怪係幾多級」(`LVL_HP`,1.0 → 3.2)同「一秒出幾多隻」。三樣嘢各自
跟自己嘅曲線行,而怪物等級帶係一個**階梯**(第 13/25/37/49 關各跳一級),
所以實際難度喺嗰四關各自跳咗三成幾 —— 一個冇人設計過、亦都冇人量過嘅斷層,
而且佢係「難度單調」呢條要求嘅天然敵人。

**新版:** `difficulty(n)` 係設計品,而雜兵血量係由佢**除返出嚟**:

```
wave_scale(n) = difficulty(n) / (等級帶平均血量倍率 × 密度)
boss_scale(n) = difficulty(n)        # boss 冇等級帶,亦唔受密度影響
```

怪物等級同密度想點行都得(佢哋而家係純粹嘅變化同視覺),總壓力照樣係設計
嗰條平滑曲線。

### 難度曲線:七段,三段係門檻坡

| 段 | 每關成長 | 對應設計目標 |
|---|---|---|
| 2–10 | 1.080 | 體驗關 |
| **11–16** | **1.230** | 坡:入「逼你升級」 |
| 17–40 | 1.105 | 逼你升級 |
| **41–46** | **1.300** | 坡:入「逼你進化一次」 |
| 47–56 | 1.090 | 逼你進化一次 |
| **57–66** | **1.369** | 坡:入「逼你雙階段 3」 |
| 67–99 | 1.050 | 逼你雙階段 3 |
| 100 | ×0.28 | 終極戰(見下) |

每一段嘅斜率係由「嗰一段玩家實際攞得到幾多力量」倒推,而嗰個係**量出嚟**嘅
(`GateSim --mode=power` 真係行一次買嘢政策再問 `Meta.tower_stats()`):

| 原型 | 力量上限(第 1 關 = 1) |
|---|---|
| A1 穩步(永不進化) | 11.6× |
| A2 tier 2 | 99× |
| A3 tier 3(未滿課) | 490 → 818× |
| A4 滿級 tier 3 | 1150× |

**點解要有坡。** 每一段嘅設計目標之間隔住一個真實嘅距離。第 10 關要平到一個
乜都冇買嘅玩家贏得到(Gate 2),而第 17 關開始要一個唔升級就打唔郁嘅玩家企喺
邊緣(Gate 3)—— 呢兩個要求之間差咗三倍幾,而三倍幾唔可能喺一關之內出現
(嗰個就係一堵牆),亦都唔可以攤勻三十關(嗰個就係兩段目標都達唔到)。
坡係中間嗰個答案:六到十關,每關明顯難咗,但每關都仲係上一關嘅延續。

### 進化躍升由 1.15 調到 1.45

`TIER_JUMP`(進化嗰一下相對「上一階課到盡」嘅躍升幅度)由 1.15 調到 1.45。

理由係量出嚟嘅:Gate 5 要求「A2 喺 71-99 關 ≤15% 而 A3 ≥55%」—— 即係話兩個
build 之間要有一段容得落廿九關嘅距離。1.15 之下量到嘅距離只有 3.8 倍
(A2 大約喺難度 9000 死,A3 撐到 34000),而三十關嘅曲線就算平到每關 +3.2%
都要用掉 2.5 倍 —— 所以 A2 死唔切,實測 71-99 仲有 19.5%。

躍升幅度打落 tier 3 係**平方**(tier 3 = STEP²),所以呢個掣對「A2 vs A3」
呢個距離嘅槓桿最大:1.15 → 1.45 令 tier 2 強 26%,但 tier 3 強 59%。

`test/EvolveTest.gd` 嗰條斷言由寫死嘅 `1.05..1.35` 改成**跟住 `TIER_JUMP` 走**
(±25%)。寫死嘅帶會令「調咗個掣」同「跌穿咗設計目標」睇落一模一樣。

### 第 100 關 —— 終極戰

十隻 boss,分三潮:

| 潮 | 開場後 | boss |
|---|---|---|
| 一 | 30s | 哥布林王 / 狼王 / 骷髏君主 |
| 二 | 92s | 岩石巨像 / 幽靈女王 / 蝠魔霸主 / 遠古樹妖 |
| 三 | 160s | 甲蟲皇 / 大祭司 / 史萊姆之母 |

* **分三潮而唔係十隻一次過:** 十隻同場分唔清邊條血條係邊隻,而且十個 boss
  機制一齊行(復活光環 + 群療 + 分裂 + 狼群)係一鑊冇人睇得明嘅粥。三潮之下
  每一潮係一個睇得出嘅陣容,而三潮加埋仍然係「全部十隻」。
* **潮與潮之間唔等清場:** 下一潮嘅計時由開場起計,所以拖得耐就一定會撞到
  重疊 —— 「多試幾場先過到」嘅壓力來源就係呢條時間線,唔係一個更大嘅血條。
* 每隻 boss 血量 = 普通 boss 嘅 0.55 倍(`FINAL_BOSS_HP_FRAC`)。十隻足血
  唔係難,係長。
* HUD 血條追住「仲生存而且血最多」嗰隻(`_final_pick_bar()`)。
* 勝利條件 = 十隻全部死晒(`final_all_dead()`),唔係「打低一隻」。

**`FINAL_SCALE = 0.28`,細過 1,而嗰個唔係手民之誤。** 第 100 關嘅難度唔係
嚟自指數,係嚟自**編排**:後期嘅輸出幾乎全部倒落 boss 血條度,所以「十隻」
本身就抵得住大約六倍指數。實測 A4 喺第 99 關(指數 107,000)贏得輕鬆,但喺
第 100 關指數 28,000 之下只贏得一成三 —— 即係話呢一關嘅**有效**難度仍然係
全遊戲最高,大約係第 99 關嘅 1.7 倍。副作用係第 100 關嘅雜兵比第 99 關軟,
而嗰個係有意留低嘅:嗰一場要玩家睇得清楚十條血條。

| 蠻力 brute | ×2.2 | ×0.88 | — | — | — | 爆發傷害 |
| 迅捷 swift | ×1.3 | ×1.42 | — | — | — | 控場 |

精英怪掉 1.9 倍金(低過佢嘅血量倍率 —— 佢係一個機會,唔係一個提款機),

### 經濟:兩條曲線擺返落同一條線上面

#### 金幣

問題(「30 關後殺幾隻怪就無限建塔」)嘅根本唔係「金太多」,係**兩條曲線唔係
同一條**:金收入跟 `wave_scale^0.45` 走,而建塔成本係一個常數。兩者嘅比率就係
`wave_scale^0.45`,喺第 100 關係六百幾倍。

三個改動,一齊落地:

1. **建塔成本擺返落同一條曲線。**
   `place_cost(id, n) = base × difficulty(n)^0.45`。「全場金收入 ÷ 一座主力塔」
   變成一個同關數**無關**嘅常數 —— 唔係「調到唔發散」,係結構上發散唔到。
2. **怪物掉金要除返「等級帶 × 密度」。**
   唔除嘅話一隻第 60 關嘅 5 級怪掉 3.6 倍金而且一秒出多三成隻,即係全場金
   收入係第 1 關嘅 4.7 倍,但建塔價得 1 倍單位。實測到嘅
   「31-50 關比率 44、51-70 關比率 95」就係嚟自呢度。
3. **遞增建塔成本。** 每多一座就貴 3%(`BUILD_COST_STEP = 1.030`)。
   單靠「成本同收入同一條曲線」做唔到「建塔數量係一個有張力嘅決定」:佢保證
   嘅係**第一座**塔嘅相對價錢唔變,但一關入面起到第二十座嗰陣,第二十一座
   仍然係同一個價。而且有一條正回饋喺度 —— 多塔 → 殺快 → 撐得耐 → 多殺 →
   多金 → 多塔,實測到第 51-70 關嘅模擬玩家可以起到成張圖。遞增成本令嗰條
   正回饋由指數變成對數。

場內每一個「絕對數」金來源(起手金、鍊金塔、點金術、邁達斯權柄)都經
`Battle.scale_gold()` 換算,唔係佢哋會隨關數變成零。

#### 魔晶

**派彩曲線分四段**(同難度分段用同一個道理:每段嘅斜率由「呢一段要玩家攞到
幾多力量」倒推):

| 段 | 每關成長 |
|---|---|
| 2–10 | 1.100 |
| 11–40 | 1.115 |
| 41–70 | 1.030 |
| 71–99 | 1.020 |
| 100 | ×2.5 |

累積目標(反解出上面四段嘅嗰三點):

* 第 41 關 ~9 萬:A2 要一座塔 + 一個魔法上到 tier 2
* 第 71 關 ~42 萬:A3 要兩件嘢都上到 tier 3
* 第 100 關 ~120 萬:A4 滿級仲爭少少,所以要 farm

**升級成本曲線 `typical_upgrade_cost(N)` 換咗個模型,唔係換咗個數字。**

舊版係一條(兩段)幾何線,由 20 關嘅實測擬合出嚟。延伸到 100 關之後佢即刻壞:
實際升級價有一個**天花板**(一條軸最貴嗰級 ≈ 249 × base ≈ 1.4 萬),而一條
幾何線去到第 100 關會叫到 23 萬。敗仗獎勵釘住呢個數,所以擬合一飄,敗仗就會
派到「一場輸 = 十六級」。

而家直接計,唔擬合:

> C(N) =「玩家到第 N 關為止賺過嘅錢,攤落佢鋪開嗰幾條軸,買到第幾級,
> 而第幾級嘅**下一級**要幾錢」

兩個輸入(累積派彩、鋪開幾多條軸 = `TYPICAL_AXES`)都係設計品,唔係實測殘差,
所以改派彩曲線 C(N) 自己跟住郁 —— 敗仗獎勵冇可能再靜靜咁飄離佢應該追蹤嗰樣
嘢(呢個係舊模型每一輪都要人手重擬合嘅原因),而且曲線自動飽和。

`TYPICAL_AXES` 由 9 調到 14。9 之下量到嘅「通關獎勵 / C(N)」喺第 9-19 關只有
1.06,而敗仗封頂係通關嘅 0.9 倍 —— 即係話「輸一場 = 一級升級」喺嗰幾關數學上
唔可能成立。14 唔係遷就上限拍出嚟:佢係**實際政策**嘅數(主力塔六軸 + 主力
魔法三軸 + 核心塔,跑完一百關實際掂過十幾條軸)。9 呢個數來自一個已經唔再
量緊嘢嘅舊 harness。

**輸場 vs 贏場比例:** 敗仗釘死喺 `1.15 × C(N)`(喺「有合理進度」= 進度分 0.5
嗰點),封頂喺通關獎勵嘅 0.9 倍,打過嘅關卡再輸只派三成。實際落到:一場有
進度嘅敗仗大約係一次首通嘅 **28-35%**,係一次重玩通關(通關獎勵一半)嘅
**60-75%**。

## 五個模擬原型

| 原型 | 定義 | 點樣得到 |
|---|---|---|
| A0 白板 | 唔升級唔進化 | 一個仙都唔使 |
| A1 穩步 | 升級軸照課,永遠唔進化 | `_spend_evolver(1)` |
| A2 進化一 | 主力塔 + 主力魔法上到 tier 2 | `_spend_evolver(2)` |
| A3 進化二 | 主力塔 + 主力魔法上到 tier 3 | `_spend_evolver(3)` |
| A4 天頂 | 一座滿級 tier 3 塔 + 三個滿級 tier 3 魔法 | **直接授予** |

A0–A3 係**打返嚟**嘅:由第 1 關開始逐關打落去,用當關實際攞到嘅魔晶買嘢,
冇任何注資。輸咗照過下一關(唔停喺第一堵牆),但魔晶收入照實,所以打得差
就真係窮。

**A1 / A2 / A3 行同一條買嘢政策,唯一嘅分別係 `target_tier`。** 第一版唔係咁:
A1 平均鋪開三座塔嘅核心軸,A2 專攻一座,結果佢哋喺第 11-40 關(兩個都仲未
進化)嘅勝率係 25% 對 100% —— 即係話 Gate 4 量到嘅「A1 打唔郁而 A2 打得郁」
其實一大半係**專精 vs 鋪開**,唔係進化。一條用嚟驗證進化系統嘅 gate,唔可以
有一個更大嘅混淆變數坐喺入面。

**A4 唔同:佢係一個狀態(「滿級階段 3」),唔係一段歷史。** 直接授予,量嘅係
天花板。佢個 build 埋單大約 220 萬魔晶,而一個一次過通關嘅玩家打到第 100 關
大約攞到 120 萬 —— 即係話 A4 唔係打到就自動有,要再 farm 一排。

### 合約策略

| 策略 | 規則 | 用嚟量 |
|---|---|---|
| 穩陣 safe | 永遠揀風險最低嗰張(平手揀倍率最細) | 難度 gate + Gate 8 期望值 |
| 貪心 greedy | 永遠揀魔晶倍率最高嗰張 | Gate 8 方差 + 上限 |

難度 gate 一律用穩陣讀數:自選增益會污染難度讀數,而合約關嘅難度應該同佢
前後嘅普通關擺得埋一齊比較。經濟 gate 兩個策略都量。

原型配對:A0/A1/A2/A3 用穩陣(佢哋喺對應段落係「捱得住就算」),A4 兩個都跑。
