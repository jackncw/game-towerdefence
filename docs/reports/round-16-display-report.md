## Bug 1:百分比顯示成小數

**根因:** 全遊戲數字得一個出口 `Upgrade.fmt_value()`,百分比靠 `_PCT_STATS`
名單 + `kind == "prob"` 認。名單漏咗五個百分比語義嘅 stat,佢哋跌落通用分支,
直接印 0-1 小數:

| stat | 邊度見到 | 舊顯示 | 新顯示 |
|---|---|---|---|
| `healcut` | 劇毒瘴氣「減回復」軸 | `0.2 → 0.2`(曲線值 0.55 印 `0.5`) | `20%`、`55%` |
| `aurapower` | 聖光塔「聖光強度」軸 | `0.2`(0.25 印一位小數) | `25%` |
| `critmult` | 箭塔/狙擊塔「暴擊傷害」軸 | `1.8` | `180%`(跟 `returnmult`/`bossmult` 先例:倍率用 %) |
| `heatmax` | 機關槍塔「熱度上限」軸 | `2` | `200%`(同 `rampmax`「增傷上限」300% 一致) |
| `supportmult` + `dmgpct`/`dpspct`/`bosspct` | 暫時冇上畫面 | — | 入咗名單,第日一擺上畫面預設就係 % |

另外兩個舊格式錯誤一齊修埋:

- **整數四捨五入食咗細步長。** 舊版一律 `int(round(v*100))`:狙擊塔「處決線」
  每級 +1.2%,顯示三級先郁一格,中間兩級睇落係空升級。而家唔係成數先印
  一位小數(`2.5%`)。
- **合約卡「每秒回復」硬寫 `%.1f`**,疊加後會印「4.0%」。而家同一條規則
  (整數預設)經 `Upgrade.fmt_pct_num()` 行,`GameData.contract_buff_text()`
  同 `BattleHUD._stacked_buff_text()` 兩邊共用。

**中英兩語:** % 符號由 code 出(`35%`),中英一樣跟喺數字後面;合約卡嘅 %
喺 i18n 字串入面(`生命 +{n}%` / `+{n}% HP`),code 淨係出數字部分 —— 兩邊
都驗過截圖。

## Bug 2:攻速小數位

**根因:** `fmt_value` 通用分支「近整數印整數、其餘一位小數」。攻速步長
0.04-0.18/級,一位小數之下「2.2 → 2.4」中間嘅級數唔郁,而 `2` 同 `2.00`
之間只有後者講得出下一級係 2.18。

**修正:** `rate`、`pulserate`(每秒次數語義)固定兩位小數,唔行通用分支。
順手刪走 `cd` 嘅 `"%.1f"` 特例 —— 佢會印「8.0 秒」,同「整數預設」規則相撞,
而家行通用規則(`8 秒`、`7.6 秒`)。

## Bug 3:下一座塔價錢顯示 vs 實收唔符

**根因:係 cache,唔係攞錯基礎價。** 第十五輪之後
`place_cost = base × gold_scale × 1.03^場上塔數`,扣賬嗰邊
(`Battle.place_tower`)永遠問 live 價;但 `BattleHUD` 起卡嗰陣將個價寫死落
卡面 Label,同時 cache 落 `{cost}` dict 俾每幀 affordability 用 —— 兩邊都
唔會再更新。所以由第二座塔起,卡面顯示嘅價(同灰唔灰到個掣)每座低 3%,
撳落去實扣嘅係新價。

**修正:** 卡 dict 加 `cost_label` 引用;`refresh()` 監住 `battle.towers.size()`,
塔數一變(起塔**同**賣塔)就重新問 `battle.place_cost()`,寫返落 Label 同
affordability cache。不變式:「卡上寫幾多 == 撳落去扣幾多」,由
TradeDisplayTest 逐座斷言。

**同類全面掃描(所有「顯示一個銀碼、實收另一個」嘅位):**

| 位置 | 顯示側 | 交易側 | 結論 |
|---|---|---|---|
| 建塔卡(抽屜 + 快捷列) | cache 咗嘅 label | live `place_cost()` | **唔一致 → 已修** |
| 賣塔面板 | `t.sell_value()` | `gold += t.sell_value()`(paid 價 ×0.7,paid 價喺 `Tower.setup` 記低) | 一致 |
| 升級介面升級掣 | `Meta.tower_up_cost()/spell_up_cost()` | `buy_*_upgrade()` 扣同一個函數 | 一致 |
| 進化掣 | `GameData.evolve_cost(is_tower, tier+1)` | `Meta.evolve()` 扣同一條路 | 一致 |
| 商店解鎖卡 | `def.unlock` / `Meta.spell_unlock_cost()` | `unlock_tower()/unlock_spell()` 同源 | 一致 |
| 結算/敗仗獎勵 | Result/Fail 顯示 `Meta.on_level_cleared/failed` **實際派彩後**回傳嘅 dict | 同一筆 | 一致 |
| 合約卡倍率預覽 | `GameData.contract_accumulate()`(揀完會變成幾多) | 通關派彩用同一個 state | 一致 |
| 圖鑑/升級介面/佈陣頁「造價」 | `GameData.place_cost(id, next_level())`(0 塔基準價) | 開場第一座 == 呢個數 | 一致(佢係「開場價」預覽;場內遞增由建塔卡負責) |
| `Tower.setup` 記 paid 價 | — | setup 喺 `towers.append` **之前**行,同扣賬同一個塔數 | 一致(次序敏感,測試釘住) |

## 自動斷言(新增 `test/TradeDisplayTest.tscn`,入咗 `run_tests.ps1` 套)

同 StatDisplayTest 一個哲學:顯示側同引擎側由兩條路入,逐項對,唔係重計公式。

- **A. 建塔 ×10:** 逐座「卡面 label == 實價 == 扣賬額」,起完下一幀卡面即刻
  跳上新價,affordability cache 跟埋。
- **B. 賣塔:** 面板掣上寫嘅退款(parse label 文字)== 實際入賬。
- **C. 升級/進化(塔+魔法):** 介面出數嗰條路 == 實扣魔晶。
- **D. 格式規則掃描:** 20 塔 + 15 魔法 × 全部軸 × 3 tier × 4 級數向量,
  百分比一定 match `^-?\d+(\.\d)?%$`、攻速 match `^\d+\.\d\d$`、
  其他數值唔准以 `.0` 結尾。
- 合計 **2034 項**,全綠。(D 部分喺改 `cd` 特例之前真係紅過 —— 佢捉到
  「8.0 秒」呢個同規則相撞嘅顯示。)

## 最終格式規則表(全 project 統一,出口 = `Upgrade.fmt_value`)

| 類型 | 規則 | 例 |
|---|---|---|
| 百分比(prob kind 或 `_PCT_STATS`) | 整數預設;唔係成數先一位小數 | `35%`、`2.5%` |
| 倍率加成 | 同百分比(×1.8 → `180%`) | `180%`、`300%` |
| 攻速/頻率(`rate`、`pulserate`) | 固定兩位小數 | `1.25`、`2.00` |
| 冷卻/秒數 | 整數預設,有小數先一位 | `8 秒`、`7.6 秒` |
| 傷害/射程/其他數量 | ≥1000 整數;近整數印整數;其餘一位小數 | `2560`、`34`、`10.5` |
| 金/魔晶銀碼 | 整數(向來如此) | `126 金` |
