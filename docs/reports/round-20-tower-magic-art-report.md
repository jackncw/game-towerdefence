### A2 摳圖

round-19 全套照搬。塔專屬嘅三樣:

1. **主體判定放寬。** 塔嘅賣點好多都係發光元素(光束塔嘅稜鏡射線、聖光塔嘅
   光柱同日冕、傳送塔嘅星空門、磁力塔嘅電弧、鍊金塔嘅法陣)。呢啲喺 alpha
   上面係半透明,喺 round-19 嘅窄 `d_soft`(d_hi+16)之下會俾一刀切走。八張
   sheet 開咗闊 `d_soft`(120–140),再靠 ramp 淡出 —— 就係 ghost 嗰單放寬嘅
   同一個做法。
2. **衛星保留加距離條件。** round-19 條「主體 bbox 外擴 20%」規則會撈埋上面
   嗰粒 ✦。加一條「離主體 ≤ 30px」,折射光線 / 日冕 / 碎片渦 / 蒸氣 / 彈殼
   全部貼住塔身,一個都冇跌;✦ 離得遠,篩走。
3. **柔光帶要反解,唔可以淨係壓綠。** 呢個係本輪最大嗰個坑。摳完第一版,
   鍊金塔 t3 嘅金色符文圈、兵營塔 t3 嘅聖光十字、迴旋鏢塔 t3 嘅氣旋、聖光塔
   t3 條光柱,源圖全部係金 / 白,出街全部變咗**螢光綠**。兩步先醫得好:
   * **matting 反解**(`unmix_soft`):`F = (C − (1−a)B)/a`,分母鎖底 0.35。
     round-19 講過呢條式喺**實色邊緣**唔work(細 alpha 一除就爆綠);但柔光帶
     係另一件事 —— 嗰度冇 core 可以補,而鎖底令佢「校得唔夠盡」而唔係「校爆」。
   * **綠度反解**(`unmix_greenness`,8 張 sheet 開):
     `r = (G − max(R,B)) / Bg 嘅同一個數`,`F = (C − r·B)/(1−r)`。條式假設咗
     前景冇綠,所以**只准**用喺色板入面根本冇綠嗰八張(箭 / 雷電 / 鍊金 /
     兵營 / 迴旋鏢 / 導彈 / 聖光 / 磁力)。毒液塔嘅綠藥水 `r = 0.65`,一反解
     就變中灰 —— 所以佢冇開。青 / 藍綠唔使驚:(80,200,210) 嘅綠度係 **−10**,
     條式當佢完全乾淨,所以磁力塔嘅青環同傳送塔嘅青綠門一條頭髮都冇少。

   量度:綠色主導像素比例,鍊金塔 t3 由 9.1% → 0%、聖光塔 t3 8.9% → 0%、
   迴旋鏢塔 t3 14.4% → 0%、磁力塔 t2 10.7% → 0%。而**應該綠**嗰批一個字冇跌:
   毒液塔 t1 仍然 10.0%、緩速力場塔 t3 18.4%、荊棘塔 t3 2.7%、光束塔 t2 5.1%。

### A3 尺寸 / 錨點 / 進化

**尺寸 —— PNG 高度一律 128,闊度逐張剪到啱剪(50–174px)。**

* 源圖每格主體約 300×280,所以 128 係**真.縮細**,唔係放大空氣。
* `GameData.TOWER_RENDER` 由 `2.0` 改做 **`0.6875`(= 88/128)**。畫面上嘅塔
  **仍然係 88px**,一步都冇郁 —— 郁咗嘅淨係源圖解像度。舊 44px 圖喺 camera
  最大 zoom 2.0 之下係 4 倍放大,而家係 1.4 倍縮細。
* **高度冇得剪**:接地線就住 node 落 61 畫布 px,所以任何一張嘅畫布半高都至少
  61+3,60 張一律 128。呢個副作用啱啱好係想要嘅 —— UI 嗰邊
  `STRETCH_KEEP_ASPECT_CENTERED` 對住 60 張同高嘅圖,縮出嚟嘅大細先會一致。
  闊度就差好遠(雷電塔 t1 得 50px、荊棘塔 t3 174px),一刀切 174 等於 55 張圖
  用緊兩倍 VRAM 去畫空氣。

**錨點 —— 接地線 y=125 / 128,即係舊圖嘅 43 / 44。**

舊 60 張 tower PNG 量過,**60/60** 實心像素底邊都喺 y=43。照抄呢個比例就等於
射程圈、選中光圈、ghost 預覽、升級面板彈出位、詛咒符文、聖光光柱全部一步都
唔使郁 —— 佢哋全部畫喺 node 原點,而 node 到接地點嘅距離維持喺 **41.94 世界
px**(舊 42.0,差 0.06px)。

**進化唔跳位。** 一座塔嘅三個 tier 共用同一個縮放倍率(全場 60 張其實共用同一
個 `k = 0.3868` —— 20 張 sheet 用同一個格距同同一個石底座模板,所以相對大細
本身就係啱嘅,郁佢反而係改美術),擺位規則係「石底座底邊 → 固定 y、石底座
水平中心 → 畫布中線」。量出嚟三個 tier 嘅接地線散開 **≤ 2 畫布 px = 1.4 顯示
px**(59/60 係 ≤1px,得磁力塔 2px),肉眼睇唔到。戰鬥中進化實測見
`25_evolve_before/after`:同一場、同一格,箭塔 / 兵營塔 / 聖光塔 / 荊棘塔 四座
同時由 t1 跳 t3,底座一粒都冇郁。

**疊加效果。** 詛咒符文(`Assets.fx("curse_rune")`)、聖光光柱、affix tint 全部
畫喺 node 原點或者 sprite 上面,錨點冇變所以層級同位置一樣冇變 —— 見
`10_towers_t3.png` 嘅聖光塔光柱同詛咒塔符文光暈。一個 offset 都唔使調。

**filter 由 NEAREST 轉 LINEAR。** 塔圖同怪物圖一樣已經唔係像素美術,而且係
**縮細**顯示(128 → 88,非整數)。NEAREST 喺非整數縮放之下會食走一行行像素。
四處要一齊轉,漏一處就會出現「呢個時刻順滑、嗰個時刻鋸齒」:`Tower.sprite`、
`Battle._Placer`(ghost 預覽 `draw_texture_rect` 跟節點嘅 filter)、`UI.tex_rect`
嘅塔 / 魔法呼叫端、Gallery。

> **踩過一個坑:`UI.tex_rect(..., smooth)` 唔可以淨係睇呼叫端。**
> 升級介面個展示位係 264px。新圖 64 / 128px 唔係整數倍,要 LINEAR;但**待補
> 清單嗰四張仲係 44px 像素圖**,而 44 × 6 = 264 啱啱好整數倍 —— NEAREST 之下
> 佢係一張銳利嘅像素畫,一行 LINEAR 就變一撻糊(第一次影地震術嗰張就係咁)。
> 所以 `tex_rect` 加咗一條:`smooth` 之下最長邊 ≤ 48px 嘅照行 NEAREST。
> Jack 補到嗰四張圖之後呢條會自動失效,唔使返嚟執。

## Part C — 地震術減弱(唯一邏輯改動)

### 問題

滿級 T3 打 **85% 生命上限**,而場上有四十座塔喺度磨,所以隨時都有大半波怪血量
低過 85% —— 一撳落去成波消失,連掉金都一次過入晒。魔法變咗一粒「贏掉呢一波」
掣,而塔喺嗰半秒入面冇存在過。

### 改法(兩步,因為有兩個獨立成因)

1. **倍率**:`pct` 曲線 `0.42 / 0.62 / 0.85` → **`0.30 / 0.38 / 0.46`**。
2. **殺傷下限**(`GameData.QUAKE_MOB_FLOOR = 0.12`):地震術唔可以令一隻
   **非 boss** 小怪跌穿生命上限嘅 12%。
   `dmg = clamp(max_hp × pct, 0, hp − max_hp × 0.12)`

第 2 步先係關鍵。淨係減倍率嘅話,血量低過新倍率嗰批照樣一炮死,而「有幾多隻
低過」係由**塔火力**決定唔係由魔法決定 —— 即係話個殺傷比率仍然會隨住玩家塔陣
變強而升返上去,呢個 nerf 撐唔過三十關。有咗下限之後,「地震術唔負責殺,佢
負責震冧同打殘,補刀係塔嘅事」變成一條**結構性**身份,唔係一個等人再調嘅數字。

### 驗證(`test/QuakeNerfTest`,已入 regression 套)

**一炮清場率。** 一波當 40 隻,血量喺 `[分佈, 1.0]` 之間均勻(模擬打緊嗰陣,
唔係全部滿血 —— 全部滿血之下舊值 0.85 一樣殺唔死人,量到會係 0%,即係睇唔到
Jack 報嘅問題):

| 階 | 血量分佈 | 舊:殺死 | 新:殺死 |
|---|---|---|---|
| t1 | 1.00(啱啱出閘) | 0% | 0% |
| t1 | 0.40 | 5% | **0%** |
| t1 | 0.05(半死) | 40% | **0%** |
| t2 | 0.40 | 38% | **0%** |
| t2 | 0.05 | 60% | **0%** |
| t3 | 0.70 | 50% | **0%** |
| t3 | 0.40 | **75%** | **0%** |
| t3 | 0.05 | 83% | **0%** |

**71–99 段 29 關 × 5 個血量分佈,最差殺傷率 = 0.0%。**
簡報畀 40%,呢度**收緊到 0%** —— 因為個下限令佢**結構性**唔可能殺死一隻非
boss,所以呢條斷言唔係「而家啱啱好收貨」,係「以後都唔可能超標」。

**控場不變式(逐個釘死喺測試度):**

| | 減弱前 | 減弱後 |
|---|---|---|
| T3 震暈 | 1.20 秒 | **1.20 秒** |
| T2 裂縫拖慢 | 40% / 3 秒 | **40% / 3 秒** |
| T3 震落飛行 | 4 秒 | **4 秒** |
| 冷卻 | 8.0 / 7.0 / 6.5 | **8.0 / 7.0 / 6.5** |
| 對 boss | 4% / 6% / 9% + 固定值 | **4% / 6% / 9% + 固定值** |

nerf 傷害,唔 nerf 控場。boss 嗰半邊一個字都冇郁。

**存在感。** 一炮對滿血小怪:t1 30% / t2 38% / t3 46%;對 boss:9% 生命上限
+ 136,947 固定(第 40 關)。魔法 bench(`SpellRuleTest`,15 × 3)照過 —— 地震術
仍然過門檻,經 boss 嗰條路(9% ≥ 5% 門檻)。**KNOWN 基線唔使重釘**:`pct` 唔喺
任何一條 Gate / 經濟基線嘅輸入入面,而 `SpellRuleTest` 嘅門檻本身冇改。

**文案跟住改。** `SPELL_QUAKE_LORE` 中英兩邊都補返「唔會直接擊殺雜兵」;順手
修咗一個一路都錯嘅講法 —— 舊文案寫「**當前**生命值百分比」,但條式由頭到尾都
係食**生命上限**。用字全部揀返字型 subset 入面有嘅(`刀` / `禦` / `盪` 三個字
唔喺 subset,所以避開咗),`I18nTest` 1158 項全過,唔使重跑 `subset_font.py`。
