## Part A — 無盡模式

### A.1 規則(全部住喺 `GameData.gd`)

| 概念 | 實現 | 點解 |
|---|---|---|
| 解鎖 | `Meta.endless_unlocked()` = `is_cleared(100)` | **推導出嚟,唔係新欄位。** `cleared["100"]` 由第一日起就寫落存檔,所以一份 1.0.1 舊存檔一開就已經帶住正確答案,零遷移步驟。加一個 flag 反而會出現「打過第 100 關但 flag 冇寫」呢種只可能係錯嘅狀態 |
| 無盡關 | `is_endless_level(n)` = `n > 100` | |
| 全 boss 關 | `is_boss_finale_level(n)` = `n % 100 == 0` | 第 100 / 200 / 300… 關,用**同一套** `FINAL_WAVES`(30 / 92 / 160 秒三潮十隻)同同一套勝利判定 |
| 合約關 | `n % 7 == 0` **而且唔係**全 boss 關 | 撞正(700 / 1400…)全 boss 關優先。呢句喺第 100 關本身一路都係咁 —— 終極戰唔應該有第二套規則疊落去 |

### A.2 難度同獎勵嘅封頂值

**天花板唔係一個數,係「第 100 關嗰一輪」** —— 對關卡**種類**嚟對:

| 關卡 | 難度 | 通關獎勵 | 首通獎勵 |
|---|---|---|---|
| 普通無盡關(101、102、…) | = 第 **99** 關 | = 第 99 關 | = 第 99 關 |
| 全 boss 關(200、300、…) | = 第 **100** 關 | = 第 100 關(即係 ×2.5) | = 第 100 關 |

**點解唔係「全部釘第 100 關」嗰個字面做法**:`difficulty(100) = difficulty(99) × FINAL_SCALE`,
而 `FINAL_SCALE < 1` —— 佢細係因為第 100 關嘅難度嚟自**十隻 boss 同場呢個編排**,
唔係嚟自指數。將嗰個指數搬去一關普通關,第 101 關就會軟過第 50 關。
所以「等值」要按種類對:普通對普通、finale 對 finale。

實測數(封頂後,`EndlessTest` B/C 兩組守住):

```
difficulty(101) = difficulty(102) = ... = difficulty(199) = difficulty(99)
difficulty(200) = difficulty(300) = ... = difficulty(100)
difficulty(500) <= difficulty(101)          # 唔會再爬
無盡段 wave_scale 嘅擺動 < 4 倍(path_factor + level_wave_norm 兩個風味修正器)
```

**獎勵同難度用同一條對應規則** —— 兩邊唔用同一條就會出現「難度平咗但派彩繼續爬」,
即係一部印鈔機。`EndlessTest` 有一條斷言就係嗰個唔准出現嘅狀態:
`level_crystal_reward(3001) <= level_crystal_reward(101)`。

順手修咗一個潛在嘅效能坑:`cumulative_reward(n)` 喺無盡段唔再行逐關 loop
(一個打到第 5000 關嘅存檔每次問 `typical_upgrade_cost()` 都要行五千次),
改成一條乘數 —— 因為封頂之後 `reward_scale` 係常數。

### A.4 存檔

**存檔格式一個欄位都冇加。** 無盡進度 = `highest_level`(佢本來就冇封頂),
解鎖 = `cleared["100"]`。所以「1.0.1 舊存檔遷移」呢件事喺結構上係一個
no-op —— 而 `SaveMigrateTest` 新加嘅兩個案例就係嗰句說話嘅可執行版本:

| 案例 | 斷言 |
|---|---|
| 1.0.1 存檔,打到第 **100** 關 | 進度冇走樣、`save_version` 冇被重新遷移、冇假 rework 退款、**無盡解鎖 = true**、**重玩減免 = false**、`tutorial_done` 補得返個預設、唔會彈新手引導、重玩第 30 關派**全額**、`next_level() > 100` |
| 1.0.1 存檔,打到第 **88** 關 | 同上,但**無盡解鎖 = false**、**重玩減免 = true**、重玩第 30 關派**半額** |

第二個案例先係重點:一個只驗「解鎖到」嘅測試證明唔到嗰個開關真係有關住嘢,
而一個永遠 true 嘅開關會靜靜咁令全部 1–100 嘅平衡讀數位移。

### A.5 取消重玩減免 —— **邊界證明**

規則:**通關第 100 關之後**,重玩任何已通關關卡派全額(通關獎勵唔再減半、
敗仗獎勵唔再打 `LOSE_REPLAY_FRAC`)。**首次通關獎勵唔受影響**,永遠一關一次
—— 減半同首通係兩件事,唔可以共用一個 bool,唔係嘅話重玩就變成一部印鈔機。

**1–100 進程中一分錢都冇變**,而呢句用三層證:

1. **結構**:`Meta.replay_penalty_active()` = `not is_cleared(100)`。一個 1–100 嘅
   campaign 由定義上冇通關過第 100 關(佢係最後一關),所以呢條規則喺嗰段
   由頭到尾都係「唔生效」。
2. **單元**:`EndlessTest` E 組(E1 進程中 / E2 解鎖後 / E3 99↔100 邊界 /
   E4 首通獎勵永遠一次)—— 兩邊都驗,唔係淨係驗「解鎖後派全額」。
3. **模擬 A/B(決定性嗰個)**:同一批 seed,**定版 code**(還原點 `7dbf6c5`,
   開一個 git worktree)vs **本輪 code**,A2 + A3 × seed 0–3 × 第 1–100 關
   完整 campaign,`--nosave`。

```
base: 800 行 / 8 檔
new:  800 行 / 8 檔
共同樣本 800 行(= 原型 x seed x 關)
逐欄完全一樣嘅行: 800
有任何一欄唔同嘅行: 0
勝負唔同嘅行: 0
A/B 判定: IDENTICAL — 逐個 seed 逐關逐欄一模一樣
```

**逐欄**唔係淨係逐勝負:ROW 行有塔數、成關收入、剩金、起手金、魔晶、
嘗試次數同戰鬥秒數,全部一齊對。一條規則可以令勝率一樣但收入唔同,
而嗰種漂移要幾輪之後先喺升級曲線度睇得出 —— 所以呢度對成行。

工具:`tools/ab_compare.py`;數據:`qa/bench/gate/r24_ab/`。

分段勝率(兩邊一樣,順手做本輪嘅 4-seed 基線):

|---|---|---|---|---|---|

## Part B — 閃退報告頁

### 做咗乜

`MainMenu._ready()` 嗰句 `CrashReport.present(self)` **拆走咗**。玩家喺任何情況
之下都唔會再見到嗰版紅字。

### 點解拆,唔係「整靚啲」

嗰個畫面係為咗查一單具體嘅 iOS 網頁版閃退而加嘅診斷工具,而佢出現嘅時機係
**開機第一眼**。對一個查緊 bug 嘅人嚟講咁啱;對一個買咗隻遊戲嘅玩家嚟講,
佢係一版紅字加一堆佢睇唔明嘅麵包屑,而且佢會喺**任何**非正常結束之後彈 ——
包括「用家自己 force-quit 咗個 app」呢種完全正常嘅事。一個嚇親玩家嘅假警報。

### 底層:**一個字都冇拆**(呢個係刻意嘅決定)

`Crash` autoload 照樣寫 session marker、麵包屑同 `user://logs/crash.log`,
`localStorage` 嗰個網頁版訊號亦都照舊。理由:嗰啲係查問題嘅**真證物**,
成本係事件級唔係逐幀級,而一單真閃退如果冇證物係一個唔可逆嘅損失。
變嘅只係「邊個睇得到」。

### 隱藏入口:設定頁**長撳版本號五秒**

點解唔係一粒掣:一粒叫「除錯記錄」嘅掣坐喺設定頁,同一版彈出嚟嘅紅字一樣,
都係喺同玩家講「呢隻嘢會壞」。五秒唔係手快撳得到嘅時間,所以唔會有人
「唔小心開咗」;冇提示、冇動畫、撳唔夠唔會發生任何嘢。

檢視器(`CrashReport`)兩種內容自動揀:

* 有偵測到上次閃退 → 顯示嗰次嘅報告(麵包屑 + 記憶體趨勢摺線)
* 冇 → 顯示**今次開機到而家**嘅麵包屑(`Crash.live_report()`,本輪新加)

第二種好緊要:一個「撳完乜都冇發生」嘅隱藏功能同壞咗一模一樣,而一部
冇閃退過嘅機上面「冇嘢睇」係一個冇用嘅答案 —— 「而家做緊乜」先係現場報告要嘅嘢。

### 守門(`LaunchUXTest` B 組)

呢組最易寫錯嘅方向係「驗主選單冇 CrashReport 子節點」—— 嗰句喺一部**冇閃退過**
嘅機上面自動成立,即係個測試喺 CI 度永遠綠色而乜都冇守到。所以測試會
**先砌返一單假閃退落 `Crash.last_crash`**,再開主選單,咁「唔彈」先係一個真結論。
另外有一組靜態掃描:十個畫面檔一律唔准再出現 `CrashReport.present(`。

### D.3 揀 0.55 嘅理由

**佢係 32 seed 之下最細嘅「A3 過唔到」嘅值。** 0.50 同 0.55 之間有一道好斜嘅崖
(12.5% → 0%)。揀崖邊上面第一格而唔係揀 0.80,係因為 Gate 6a 要嘅只係
「A3 過唔到」,而喺滿足佢嘅前提下**越軟越好** —— 一個真人玩家嘅強度低過
harness 嘅 A3(佢用 `strong` 策略:擺位按路程覆蓋、升級軸按邊際戰力、
魔法按威脅施放),所以每一分多餘嘅難度都係直接由玩家嗰邊找數。

0.55 之下第 100 關嘅指數 = 第 99 關嘅 55%(出街版係 5.2%),而「十隻 boss 同場」
呢個編排本身抵得住大約六倍指數 —— 即係**有效**難度大約係第 99 關嘅 3.3 倍。

### D.4 Gate 6b(A4 10–30%)—— **量到係做唔到嘅**

呢度唔係「差少少」:

* `FINAL_SCALE` 由 0.052 掃到 **300**(**5,769 倍**),A4 **每一格都係 16/16 全勝**。
* 平均用時只由 166.6 秒郁到 174.4 秒 —— 而第三潮 160 秒先出場,即係話成場嘅
  長度**由編排決定,唔係由血量決定**。
* 場上最深嗰隻怪由路程 9% 只行到 44%。以 `frac ∝ scale^0.15` 外推,要行到基地
  (frac = 1.0)大約要 `FINAL_SCALE ≈ 120,000`。
* 兩個「唔靠血量」嘅掣(全精英化 / 壓縮潮距)一樣係 16/16。

**點解**:A4 係一個**授予**嘅 build —— 箭塔 tier 3 六條軸全部滿級 + 三個滿級
tier 3 魔法,而且喺第 100 關起到約 45 座塔。佢同 finale 之間差咗兩三個數量級,
而 finale 冇任何一個掣夠長去接得返。同一批掃描入面 A3 由 100% 跌到 0% 只需要
FINAL_SCALE ×10.6,即係**A3 同 A4 之間差咗成三個數量級**。

### D.5 呢個位嘅設計代價(**要 Jack 睇**)

滿足 Gate 6a 嘅代價係:**第 100 關而家係一道「A3 一定過唔到、A4 一定過」嘅硬門檻**,
而無盡模式係鎖喺呢道門後面嘅。

| FINAL_SCALE | A3 第 100 關 | 意思 |
|---|---|---|
| 0.32 | 37.5% | 一到就贏得三分一,冇「終局」感 |
| **0.50** | **12.5%** | **「多試幾場先過到」嘅手感落喺真正會行到嗰度嘅原型身上(平均試 8 場)。但 Gate 6a FAIL** |
| **0.55(出貨)** | **0%** | **Gate 6a PASS。要再 farm 到接近滿級先贏得到** |

改法係一個常數:`GameData.FINAL_SCALE`。我照 brief 嘅明文目標揀咗 0.55,
但如果 Jack 親手打落去覺得「打唔到」多過「多試幾次」,**0.50 就係嗰個
你想要嘅手感**,而佢唯一嘅代價係 Gate 6a 由 PASS 變 FAIL —— 而嗰條 gate
本身係第十五輪寫嘅,寫嗰陣冇一把量得到嘢嘅尺。

## Part E — Gate 5a 收尾:**三個掣量到全部冇效,一個都冇出貨**

### E.1 揀邊個掣、點解

D5(第 21 輪報告)列咗四個選項。我揀咗「`BOSS_SPAWN` rate」呢條路,但**唔用
靜態版**,理由:第十七輪已經試過直接抬高 goblin / golem / beetle 三族嘅 rate,
唔夠殺。本輪查到點解 —— 第十八輪加咗 `level_wave_norm()`,而佢會將「boss 期
出怪多」讀成「呢關本身好毒」,於是**同一關嘅雜兵血量被除返軟咗**,一個 rate
加成有一半係自己抵銷自己。

所以實裝嘅係一個**圍城斜坡**(`BOSS_SIEGE_RAMP`):boss 出場之後,雜兵出怪率
由 1.0 線性爬到 `MAX`。三個理由:

1. 佢唔係「呢一關更毒」,係「**你拖得越耐越毒**」—— 而 A2 喺 71–99 剩返嘅
   勝場全部係「慢 boss 殺唔到你,所以你有無限時間磨」嗰種。
2. `level_wave_norm` 用一個 30 秒嘅**靜態**模型估 boss 期,所以一個只喺 30 秒
   之後先咬人嘅斜坡由結構上就唔會被佢補償走。
3. 佢係**全關卡一致**嘅(唔係逐關系數),所以唔會製造新嘅難度孤島。

### E.2 讀數:郁唔到(A2 + A3,seed 0–3,完整 1–100 campaign)

| 區間 | 對照 | 斜坡 2.0/90s | 斜坡 3.0/90s | 斜坡 3.0/45s |
|---|---|---|---|---|
| A2 71–80 | 35.0% | 32.5% | 32.5% | 22.5% |
| A2 81–90 | 15.0% | 17.5% | 25.0% | 22.5% |
| A2 91–99 | 2.8% | 5.6% | 2.8% | 8.3% |
| **A2 71–99(Gate 5a)** | **18.1%** | **19.0%** | **20.7%** | **18.1%** |

成對翻轉:贏→輸 10–16 場,輸→贏 10 場 —— **對稱,即係噪音。**
三個孤島(71 / 78 / 81)喺每一個配置之下都仍然係 **100%**。

### E.3 第二個掣:71–99 拆兩段(D5 嘅第一個掣)

A2 剩返嘅勝場**唔係**平均分佈(71–80 佔 35%、81–90 佔 15%、91–99 佔 2.8%),
所以一段式斜率郁唔到呢個分佈 —— 斜率加得多,段尾就一齊變成 A3 都過唔到。
所以拆做「門檻坡 + 平段」,同 11–16 / 41–46 / 57–62 三個現有門檻坡一樣嘅形狀。

| 區間 | 對照 | 71-80 坡 1.090 / 81-99 平 1.038 | 71-80 坡 1.130 / 81-99 平 1.020 |
|---|---|---|---|
| **A2 71–99(5a)** | **18.1%** | **16.4%** | **17.2%** |
| A3 71–99(5b) | 60.3% | 61.2% | 58.6% |
| A2 41–70(4b) | 79.2% | 79.2% | 79.2% |

配置 b 令第 80 關硬咗 **1.87 倍**(≈ +14 個等值關數),而 5a 只郁咗 0.9 點,
**孤島照樣 100%**。

### E.4 根因:唔係難度曲線,係一個**收入 → 塔數嘅雙峰雪球**

逐關拆 A2 喺 71–84 嘅實測(4 seed):

| 關 | boss 族 | 勝率 | 最深路程 | **塔數** | **成關收入** |
|---|---|---|---|---|---|
| **71** | goblin | **100%** | 0.7 | **28.0** | **1446** |
| 72 | wolf | 25% | 1.0 | 22.8 | 1069 |
| 73 | skeleton | 0% | 1.0 | **8.2** | **8** |
| 74 | golem | 50% | 1.0 | 19.5 | 788 |
| 75 | ghost | 75% | 0.9 | 23.2 | 1096 |
| 76 | bat | 0% | 1.0 | **8.2** | **6** |
| **78** | beetle | **100%** | 0.7 | **36.0** | **1974** |
| 79 | cultist | 0% | 1.0 | **9.0** | **28** |
| 80 | slime | 0% | 0.5 | **6.8** | 176 |
| **81** | goblin | **100%** | 0.6 | **30.5** | **1637** |
| 82 | wolf | 0% | 1.0 | 10.2 | 125 |
| 83 | skeleton | 0% | 1.0 | 10.5 | 143 |
| 84 | golem | 50% | 0.9 | 19.8 | 818 |

**贏嗰啲關 28–36 座塔、收入 1400–2000;隔籬輸嗰啲得 7–10 座、收入 6–143。
相鄰關之間差成 100–200 倍。**

即係話呢啲關唔係「難度啱啱好」,係**兩個完全唔同嘅局**:

* 開場捱得住(慢 boss / 冇毒機制嘅家族)→ 殺得多 → 有金 → 起到 30 座塔
  → 之後幾多血都食得住(所以加 1.87 倍血量,最深路程由 0.667 郁到 0.633,
  **郁咗嘅方向仲係反嘅**)。
* 開場捱唔住(復活 / 相位 / 飛行 / 群療 / 分裂)→ 幾秒就穿 → 冇金 → 8 座塔 → 死。

呢個就係第十五輪記低嗰個「打得順 → 多金 → 更順」嘅正回饋,而佢喺 71–99 段
被一個**家族剋制**效應觸發:`FAM_MECH_TOUGH` 用一個純量估「一隻怪有幾硬」,
但一個冇對空手段嘅 build 面對飛行族唔係「硬 1.05 倍」,係一個硬剋制。

**任何加血量嘅掣都郁唔到呢個結構** —— 佢哋加落去嘅嘢會俾同一批關卡自己
多出嚟嗰二十座塔食晒。

### E.5 所以本輪出貨嘅係:**冇改動**

* `BOSS_SIEGE_RAMP_MAX` 預設 **1.0**(即係關咗,行為同出街版一模一樣)。
* `WAVE_G_71_80` / `WAVE_G_81_99` 預設 **1.0466 / 1.0466**,即係同舊嗰條
  單段曲線**逐個關數一模一樣**。拆做兩個變數係為咗下一輪校準可以由 CLI 掃。

兩個機制嘅 code 同 CLI 掣都留低,而且喺註解入面寫明「量過、冇效、點解」——
一個試過失敗嘅掣如果冇留低記錄,下一輪會有人再試一次。

### E.6 下一輪要郁嘅嘢(建議)

唔係難度曲線,係**開場存活 / 收入落差**:

1. **收入落底**:一關嘅收入唔應該同「你捱唔捱得住開場」呈 100 倍關係。
   ⚠️ 第十五輪試過個天真版(起手金 200→450 + 掉金 ×0.5),結果**每個原型
   都變強**,Gate 4a / 5a 一齊跌穿 —— 所以要嘅係一個**落底**(輸嗰陣至少
   派到起到 N 座塔),唔係搬走浮動部分。
2. **家族剋制入曲線**:`FAM_MECH_TOUGH` 而家係一個「對所有 build 一樣」嘅
   純量。實測講緊嘅係佢對一個 tier-2 build 同一個 tier-3 build 完全唔同。

## Part F — 上架 QoL

### F.1 首戰引導(之前**完全冇**)

四張一次性提示卡,只喺一個**全新存檔**嘅第一場戰鬥出一次,整場凍住,
隨時可以撳「跳過」。中英雙語。

| 頁 | 講乜 |
|---|---|
| 1 | 拖卡起塔(綠色 = 放得,紅色 = 放唔得) |
| 2 | 魔法一樣咁拖出去用,放手嗰點就係施法位置 |
| 3 | 右上角速度掣 1x / 3x / 5x,唔影響難度 |
| 4 | 用魔晶喺「升級」課塔同魔法,六條軸滿晒就進化;商店解鎖新塔 |

**點解係四張卡而唔係逐格高亮嘅互動教學**:互動教學要 hook 住每一個真操作
(拖到一半、放錯位、撳錯掣),而每一個 hook 都係一條只會喺教學入面行到嘅
code path —— 呢隻遊戲嘅輸入層(卡 `gui_input` 搶走成個手勢)本身已經係全
project 最多陷阱嗰一忽,再疊一層狀態機落去係一個唔值得嘅風險。

**兩個唔可以漏嘅條件**:

* `should_show_tutorial()` 要求 `highest_level == 0` **而且** `tutorial_done` 冇寫過。
  第二個條件本身唔夠 —— 一份 1.0.1 存檔冇 `tutorial_done` 呢個 key,淨係睇佢
  就會令一個已經打到第 80 關嘅玩家食一疊教佢點拖卡嘅提示。
* `_open_tutorial()` 喺 `Flow.nav_enabled == false`(headless harness)**一定唔開**。
  一張等人撳嘅卡喺 harness 度就係一張永遠冇人撳嘅卡,而 `tutorial_pending`
  令 `Battle._process` 早返 = 成個 harness 靜靜咁掛死喺第 1 關。同一類事已經
  咬過三次(逢 7 嘅合約關坐死 BossHealTest / BossSpawnTest / SoakTest),
  所以用返同 `_set_world_paused()` 一模一樣嗰個旗,唔靠每個 harness 記得自己關。
